## Token 为什么不是简单的“一个汉字或一个单词”

计算机需要把文本映射成有限词表里的整数编号。若按整词建词表，生僻词会爆炸；若按单字符处理，序列又会过长。常见 Tokenizer 因而采用子词：高频片段可以整体出现，低频词则拆成更小单元。

同一句话在不同模型里可能得到不同 Token 数。Token 数会直接影响上下文容量、推理费用和速度，所以“多少字”并不等于“多少 Token”。中文、英文、代码和数字的切分效率也不同。

## 从 Token ID 到 Embedding 向量

Token ID 只是索引，本身没有大小关系。Embedding 层维护一个形状为“词表大小 × 隐藏维度”的可学习矩阵，每个 ID 取出其中一行，得到连续向量。训练过程中，含义相近或使用环境相似的 Token 往往形成某些可利用的几何关系。

若 batch 大小为 `B`、序列长度为 `T`、隐藏维度为 `D`，Embedding 输出通常是 `[B, T, D]`。后面每一层 Transformer 都在保持或变换这组位置向量。

## 模型为什么还需要知道位置

注意力本身会比较任意两个位置，却不会天然知道“谁在前、谁在后”。因此模型要加入位置信息。绝对位置编码给每个位置一个向量；相对位置偏置描述两者距离；RoPE 则通过旋转 Query 和 Key，让点积包含相对位置信息。

位置方法还影响模型能否外推到更长上下文。把窗口从 8K 拉到 128K 不是简单改一个数字，还要处理位置缩放、训练分布、显存和注意力计算成本。

## Tokenizer 带来的真实边界

特殊 Token 用于表示开始、结束、填充、角色或工具调用边界；聊天模板再把系统、用户和助手消息拼成模型训练时见过的格式。模板不匹配时，模型能力可能明显下降。

数字被拆分的方式会影响算术，代码缩进和空格会影响序列，罕见语言可能需要更多 Token。分析模型错误时，不要只看原始文字，也要查看实际 Token 与模板。
