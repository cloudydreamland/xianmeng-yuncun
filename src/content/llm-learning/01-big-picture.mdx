## 大模型不是资料库，而是“下一个 Token”预测器

把一句话切成一串 Token 后，语言模型接收前面的 Token，给词表中每个候选 Token 一个概率，再选出下一个。不断把新 Token 接回输入，就形成一段回答。它看起来会聊天、翻译和写代码，底层却始终在重复“根据上下文预测下一步”。

“预测”并不等于随机猜。训练让模型从海量文本里压缩出语法、事实关联、写作风格和一定的推理模式。因此，模型参数更像一套分布式的规律，而不是可以逐条检索的百科数据库。

> 先记主线：文本 → Token → 向量 → 多层 Transformer → 下一个 Token 的概率。

## 参数、上下文和知识分别是什么

参数是训练得到的数字权重，决定模型如何变换输入；上下文是本次请求真正放进窗口里的 Token；外部知识则来自搜索、数据库或工具。三者不能混为一谈。

模型参数中的知识更新慢，且可能记错；上下文中的信息更新快，但受窗口长度限制；外部知识可以实时更新，却要处理检索质量和权限。后面的 RAG 与 Agent，正是在弥补“只靠参数回答”的局限。

## 训练和推理是两套完全不同的工作

训练阶段会准备样本、执行前向计算、计算损失、反向传播梯度并更新参数，目标是让正确的下一个 Token 概率更高。它计算量大、需要保存中间激活，还要长期反复迭代。

推理阶段通常不再更新参数，只做前向计算并逐 Token 生成。它更关心首字等待时间、每秒生成速度、显存容量和多人并发。因此，“模型能训练”和“模型能高效上线”是两个工程问题。

## 一条适合零基础的学习顺序

先理解 Token、向量和训练直觉，再进入 Transformer；随后看预训练、微调与对齐，最后学习推理、RAG、Agent、评测和多模态。不要一上来背各种模型缩写，因为它们大多只是这条主干上的不同取舍。

读完每章，可以做三件事：画一条数据流、用自己的话写三句话、再去做对应面试题。公式记不住没有关系，先保证每个符号代表什么、变化前后形状是什么。
