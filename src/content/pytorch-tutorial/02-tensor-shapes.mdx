### 本节目标

本节围绕“用 shape 推理，而不是靠试错”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

每次运算前先写出输入与输出形状。元素级运算保持可广播形状，矩阵乘法收缩相邻的内维。形状推理是排查注意力错误最省时间的方法。

核对“用 shape 推理，而不是靠试错”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
x = torch.randn(2, 5, 8)      # B,T,C
w = torch.randn(8, 16)        # C,D
y = x @ w                     # B,T,D
print(y.shape)                 # torch.Size([2, 5, 16])
```

### 运行结果与观察

输出应明确显示每个 Tensor 的 shape、ndim、dtype 与 device；改变一个轴后，只允许与该轴相关的输出变化。若 shape 虽能广播但语义错误，本节仍判定未通过。

### 常见错误

- 只凭元素总数猜形状；把 batch 维和 sequence 维交换后仍认为语义相同。
- 排查“用 shape 推理，而不是靠试错”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

线性层本质上对最后一维做变换，因此一份权重可同时处理所有 batch 和 token。

### 动手练习

推导 `[4, 128, 768] @ [768, 3072]` 的输出形状和乘加量级。

<details className="lesson-answer">
  <summary>查看参考答案与验收点</summary>
  <p>先把每个轴写成语义：例如 `[B,T,C]` 分别是批次、序列和隐藏维；再用 `assert tensor.shape == (...)` 固化预期。</p>
</details>

本节围绕“索引、切片与布尔选择”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

基础切片通常返回共享存储的视图，高级索引常生成新 Tensor。布尔掩码适合筛选，但会压平被选位置；要保留原布局，常用 `masked_fill` 或 `where`。

核对“索引、切片与布尔选择”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
x = torch.arange(12).reshape(3, 4)
rows = x[:2]                       # view-like slice
mask = x % 2 == 0
selected = x[mask]
kept_shape = x.masked_fill(~mask, -1)
print(selected, kept_shape, sep='\n')
```

### 运行结果与观察

切片结果的 shape 应与所选区间一致，布尔索引只保留条件为真的元素；练习中应手算元素数量，再与 `numel()` 对照。

### 常见错误

- 原地修改切片时没意识到原 Tensor 也改变；混淆 mask 的正负语义。
- 排查“索引、切片与布尔选择”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

padding mask 与 causal mask 都依赖布尔语义；先明确 `True` 表示“保留”还是“屏蔽”，不同 API 约定可能不同。

### 本节目标

本节围绕“reshape、view、transpose 与 contiguous”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

`view` 只改变元数据，要求内存布局兼容；`transpose` 改变步长后常不连续，可能需要 `contiguous`。`reshape` 会尽量返回视图，必要时悄悄复制，使用更方便但要理解成本。

核对“reshape、view、transpose 与 contiguous”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
x = torch.randn(2, 3, 4)
y = x.transpose(1, 2)             # [2,4,3]
print(y.is_contiguous())
z = y.contiguous().view(2, 12)
r = y.reshape(2, 12)
print(z.shape, r.shape)
```

### 运行结果与观察

输出应明确显示每个 Tensor 的 shape、ndim、dtype 与 device；改变一个轴后，只允许与该轴相关的输出变化。若 shape 虽能广播但语义错误，本节仍判定未通过。

### 常见错误

- 把 `view` 当成任意换轴；不清楚 `reshape` 何时产生额外复制。
- 排查“reshape、view、transpose 与 contiguous”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

多头注意力频繁在 `[B,T,C]` 和 `[B,H,T,D]` 间变形；忘记转回布局是最常见实现错误之一。

## 广播机制与隐形内存

### 本节目标

本节围绕“广播机制与隐形内存”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

广播从末尾维度向前比较：两个维度相等，或其中一个为 1，才可兼容。`expand` 通过步长制造逻辑视图，通常不复制；`repeat` 真正复制数据。

核对“广播机制与隐形内存”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
scores = torch.randn(2, 4, 8, 8)     # B,H,T,T
mask = torch.tril(torch.ones(8, 8, dtype=torch.bool))
scores = scores.masked_fill(~mask, float('-inf'))
probs = scores.softmax(dim=-1)
print(probs.shape)
```

### 运行结果与观察

输出概率最后一维的和应接近 1，被屏蔽位置应为 0；同时检查没有复制出不必要的 `[B,H,T,T]` 实体掩码。

### 常见错误

- 把错误形状广播成功却得到错误语义；用 `repeat` 制造巨大掩码浪费显存。
- 排查“广播机制与隐形内存”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

一个 `[T,T]` 因果掩码可以广播到所有 batch 和 head，无需复制成 `[B,H,T,T]`。

### 动手练习

### 本节目标

本节围绕“矩阵乘法、bmm 与 einsum”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

`matmul` 支持批量广播，`bmm` 专门处理三维批矩阵，`einsum` 用轴标签表达收缩关系。先掌握普通 `@`，复杂轴关系再用 `einsum` 提高清晰度。

核对“矩阵乘法、bmm 与 einsum”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
q = torch.randn(2, 4, 6, 8)  # B,H,T,D
k = torch.randn(2, 4, 6, 8)
s1 = q @ k.transpose(-2, -1)
s2 = torch.einsum('bhtd,bhsd->bhts', q, k)
print(torch.allclose(s1, s2), s1.shape)
```

### 运行结果与观察

两种写法的输出 shape 与数值应一致，`allclose` 返回 True；注意力权重沿 key 轴求和应接近 1。

### 常见错误

- 在热路径中过度使用难读的 einsum；忽视临时张量大小。
- 排查“矩阵乘法、bmm 与 einsum”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

注意力分数的两个序列轴分别代表 query 位置和 key 位置；给轴命名能减少“转置错一维”的概率。

## 数值稳定：softmax、logsumexp 与归一化

### 本节目标

本节围绕“数值稳定：softmax、logsumexp 与归一化”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

指数函数增长很快。稳定 softmax 会先减去最大值，交叉熵内部也会组合 `log_softmax` 与 NLL，避免先算概率再取对数。数值稳定不是小优化，而是训练能否进行的前提。

核对“数值稳定：softmax、logsumexp 与归一化”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
x = torch.tensor([1000., 1001., 1002.])
naive = torch.exp(x) / torch.exp(x).sum()
stable = torch.softmax(x, dim=0)
manual = torch.exp(x - x.max()) / torch.exp(x - x.max()).sum()
print(naive, stable, manual, sep='\n')
```

### 运行结果与观察

朴素指数写法应出现 `nan`，框架 softmax 与减最大值的手写版本应给出相同有限概率，从而直观看到稳定化的作用。

### 常见错误

- 手写 `log(softmax(x))`；归一化时把错误维度当作类别维。
- 排查“数值稳定：softmax、logsumexp 与归一化”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

注意力、语言模型词表 softmax 和对比学习都可能遇到大 logits；优先使用框架提供的融合稳定算子。

## 原地操作、别名与内存安全

### 本节目标

本节围绕“原地操作、别名与内存安全”展开。运行示例后修改一个维度或索引，写出每步 shape，并检查广播、视图和数值结果。

### 清晰讲解

带下划线的方法通常是原地操作。它能节省一部分内存，但会修改共享存储并可能破坏 autograd 为反向传播保存的中间值。先写正确的非原地版本，再根据 profiler 证据优化。

核对“原地操作、别名与内存安全”每一步的轴语义、shape 与存储关系，广播后的数值也要符合预期。

### 代码示例

```python
import torch
x = torch.tensor([1., 2., 3.], requires_grad=True)
y = x * 2
safe = torch.relu(y)
loss = safe.sum()
loss.backward()
print(x.grad)
```

### 运行结果与观察

`view` 与原 Tensor 的 `data_ptr()` 应相同，`clone` 应不同；对别名做原地修改会影响原值，而副本保持不变。

### 常见错误

- 看到方法名相似却没注意下划线；对叶子 Tensor 做需要梯度的原地修改。
- 排查“原地操作、别名与内存安全”时只确认 shape 能运行，没有检查轴语义、广播方向或内存关系。

### 与大模型方向的连接

大模型训练显存紧张，但随意原地改激活可能触发 version counter 错误；检查点和融合算子往往是更稳妥的优化路径。
