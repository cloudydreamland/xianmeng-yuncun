# 管理端认证与维护

## 边界

- 公开站仍是只读发布内容；私人数据只在管理项目 D1 中。
- 通行密钥采用标准 WebAuthn，使用维护中的 SimpleWebAuthn 库；不自制签名协议，不收集设备 PIN、指纹或面容。
- 一个 `auth_admin` 单例、最多八把密钥。公开注册不存在；首次绑定需要 256 位随机初始化凭据。只有哈希配置到 Cloudflare，原文仅由管理员本人输入。
- 管理端固定 HTTPS Origin 和 RP ID。更换域名后，原有密钥不能自动在新域名使用，必须设计受控重新绑定；不能仅修改 Origin 就宣称无迁移切换。
- 登录、注册均强制设备用户验证；挑战限时五分钟、绑定 HttpOnly Cookie、服务端原子消费，拒绝跨站 iframe 和重复挑战。
- 会话令牌由安全随机数生成，数据库仅存哈希；最长 12 小时，一小时无活动失效。退出撤销数据库会话，删除设备撤销对应会话。
- 恢复码是高熵随机值，数据库仅存哈希，每个仅能使用一次。恢复会话只能绑定新密钥；完成后原有密钥、会话和恢复码全部撤销。
- 修改安全设置需要五分钟内重新验证身份。整个事务会再次确认会话未被撤销，避免并发越权。绑定操作与唯一管理员创建在 D1 原子批次中执行。
- 所有写接口要求 JSON 和精确同源 Origin；认证请求体最大 32 KiB；认证操作每 IP 每五分钟 30 次，全局 160 次。达到限额会暂时拒绝认证，不降级放行。
- 全站 Functions 中间件默认保护页面，API 独立重复校验会话；异常不回退静态页面。仅登录页、登录接口、静态脚本字体和 robots 可匿名访问，均禁止缓存和索引。
- CSP 的脚本随机 nonce、禁止 iframe/object、禁止外部连接等为附加防护，不代替安全编码与输入校验。

## 上线核对

1. 构建与测试通过后，先迁移 `0002_passkey_auth.sql`，不删除 `private_records` 或旧快照数据库。
2. 管理项目使用 `admin/wrangler.jsonc`，生产固定 Origin；预览项目不得绑定另一套宽松 Origin 访问生产 D1。
   在 Cloudflare 管理项目的 Production 与 Preview 设置中，将 Runtime → Fail open/closed 设置为 **Fail closed**。这是平台级额度超限策略，中间件无法替代它；不得让配额耗尽时绕过函数返回静态页面。
3. 管理员本人按本地初始化说明配置 Secret 和绑定设备，离线保存恢复码，最好另绑独立备用设备。
4. 完成后删除初始化 Secret 并重新部署，确认匿名页面跳登录、所有私人 API 拒绝匿名、真实设备可以退出与再登录。
5. 线上实际写入/刷新测试需要管理员登录后进行。浏览器内置预览可能不支持通行密钥，优先使用正常系统浏览器。

## 维护及恢复

- 定期检查身份库和构建依赖安全公告、更新并运行单元测试与真实运行环境测试，不承诺零漏洞。
- 丢失一个设备：使用备用设备登录，在“账户与通行密钥”移除丢失设备，并退出所有会话。
- 没有可用设备：使用一条离线恢复码绑定新设备，保存替换后的恢复码。取消设备注册会消耗已提交的恢复码。
- 设备和恢复码均丢失：通过已验证身份的 Cloudflare 账户进行受控账户恢复；没有公开邮件重置入口。先备份 D1，不要删除私人记录或随意清空认证表。
- Cloudflare/GitHub 管理账号本身也须启用多因素认证；掌握部署权限的人可以改变验证代码，这是此架构的信任边界。
- 备份导出只包含私人记录，不包含认证密钥、会话或恢复码。定期离线保存私人 JSON，免费额度或服务故障可能暂时影响可用性。

## 测试

`pnpm test:unit` 覆盖真正的公钥签名、错误 Origin/挑战/签名/用户句柄、设备 UV、挑战重放、初始化关闭、恢复撤销、CSRF、限速及记录 CRUD。

`pnpm test:e2e:auth` 用隔离本地 D1、真实 Cloudflare Workers 运行时和 Chromium 虚拟验证器跑完整注册/登录/保存/退出流程；测试凭据不用于生产。
